## 2) المعمارية القياسية (Best-Practice) التي يتبعها كبار المطورين

المبدأ المركزي: **الـ CAPTCHA هو «مصفاة» ترفع التكلفة، وليست «بوابة» تُثبت الهوية.** الاعتماد عليه وحده خطأ شائع. البنية الصحيحة طبقات:

```
[1] Edge / WAF  →  [2] Challenge  →  [3] Identity Gate  →  [4] Risk Scoring  →  [5] Trust Ladder
```

**[1] طبقة الحافة (Edge / WAF + Bot Management)**
- Rate limiting بمفاتيح متعددة: IP، /24، device fingerprint، نطاق البريد، **سرعة التسجيل** (velocity).
- حلول Bot Management (Cloudflare Bot Management / Akamai / DataDome / Kasada) — تجمع إشارات الشبكة + الجهاز.
- **هذه الطبقة هي ما يوقف «الكمّ» الذي يعجز Turnstile وحده عن ردعه.**

**[2] طبقة التحدي (Turnstile) — مع تحقق إجباري على السيرفر**
لا تثق بالـ client أبداً. تحقق دائماً من الجهة الخلفية:

```python
resp = requests.post(
    "https://challenges.cloudflare.com/turnstile/v0/siteverify",
    data={"secret": SECRET, "response": token, "remoteip": client_ip},
    timeout=5,
)
d = resp.json()
if not d.get("success"):
    reject()
# Best practices:
#  - تأكد أن d["hostname"] يطابق مضيفك المتوقع
#  - فرض single-use: خزّن (hash) الـ tokens المستخدمة مؤقتاً
#  - fail-closed: إذا تعذّر الوصول لنقطة التحقق → رفض (للتسجيل)
```

**[3] بوابة الهوية — البوابة الحقيقية**
- **تحقق من البريد** (magic link / code) → يفصل البشري عن الآلي لأنك تحتاج صناديق بريد حقيقية.
- **OTP جوال** للقيم الأعلى.
- هذه الطبقة ترفع تكلفة الأتمتة إلى «تكلفة اقتناء بريديات/أرقام حقيقية» — تكلفة عالية جداً، بعكس PoW الذي يضيف 0.03 ثانية.

**[4] طبقة الخطورة (Risk Scoring)**
دمج الإشارات: سمعة IP، اتساق بصمة الجهاز، إشارة السلوك، نطاق البريد (disposable؟)، السرعة، سجلّ الإساءة → نقطة → إجراء: `allow / step-up / block`. أضف **honeypots** + **مصائد زمنية** (استمارة اكتملت في < ثانيتين = bot).

**[5] سلّم الثقة بعد التسجيل (Progressive Trust)**
الحساب الجديد يبدأ بصلاحيات محدودة، وتُفتح الإجراءات تدريجياً (بريد موثّق، عمر الحساب، …).

**[6) المراقبة (Observability)**
سجّل نتائج `siteverify` وأكواد الخطأ، وآنِر على التكتّلات (مثلاً N فشل/دقيقة)، وأعد ضبط rate-limit تلقائياً عند رصد burst.
