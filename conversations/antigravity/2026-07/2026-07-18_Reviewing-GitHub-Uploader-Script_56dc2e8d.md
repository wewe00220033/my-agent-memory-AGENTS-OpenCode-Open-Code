# ثالثًا: مشاكل منطق المزامنة

## 1. السكريبت يدمج الملفات لكنه لا يحذف الملفات القديمة

الدالة `copy_tree` تستبدل الملفات الموجودة وتضيف الجديدة، لكنها لا تحذف ملفًا موجودًا في المستودع ولم يعد موجودًا في الأرشيف.

لذلك السكريبت حاليًا ليس **مزامنة كاملة**، بل هو:

> نسخ وإضافة وتحديث فقط.

حتى مع:

```python
git add -A
```

لن يكتشف Git حذف الملفات القديمة، لأن السكريبت لم يحذفها أصلًا من مجلد الـClone.

## يجب أن نحدد الوضع المطلوب

### وضع الدمج `merge`

- يضيف الملفات الجديدة.
- يحدث الملفات الموجودة.
- يحتفظ بالملفات القديمة غير الموجودة في الأرشيف.

هذا هو السلوك الحالي تقريبًا.

### وضع المطابقة `mirror`

- يجعل محتوى المستودع مطابقًا تمامًا للأرشيف.
- يحذف من المستودع أي ملف غير موجود في المصدر.
- يحافظ فقط على ملفات مستثناة مثل:
  - `.git`
  - وربما `.github`
  - وملفات إعداد محددة.

### اقتراحي

نجعل الوضع الافتراضي آمنًا:

```text
--mode merge
```

ونسمح بالمطابقة الكاملة صراحةً:

```text
--mode mirror
```

وفي وضع `mirror` يجب عرض الملفات التي ستُحذف وطلب تأكيد، أو استخدام:

```text
--yes
```

للتشغيل الآلي.

## 2. تحليل تغييرات Git غير كامل

الكود يتعامل فقط مع:

```python
A = Added
M = Modified
```

لكنه يتجاهل:

- `D`: ملف محذوف.
- `R`: إعادة تسمية.
- `C`: نسخ.
- `T`: تغيير نوع الملف أو صلاحية التنفيذ.
- `U`: تعارض.
- `B`: تغيير كامل أو broken pairing.

وهذا قد ينتج عنه موقف خطير:

- توجد تغييرات مجهزة في Git.
- لكن ليست `A` أو `M`.
- السكريبت يقول: “لا توجد تغييرات”.
- لا ينشئ Commit.
- ثم قد يحذف ملف الأرشيف الأصلي.

### المطلوب

- دعم جميع الحالات المهمة.
- اعتبار وجود أي staged diff تغييرًا.
- إضافة قوائم:
  - `new_files`
  - `updated_files`
  - `deleted_files`
  - `renamed_files`
  - `type_changed_files`
- إيقاف العملية إذا ظهرت حالة `U`.

## 3. تحليل أسماء الملفات ليس قويًا بما يكفي

الاستخدام الحالي:

```python
git diff --cached --name-status
```

ثم تقسيم الأسطر قد يفشل مع أسماء ملفات تحتوي:

- Tabs.
- Newlines.
- رموز غير معتادة.
- مسارات إعادة التسمية التي تحتوي مسارين.

الأفضل استخدام خرج مناسب للبرامج:

```text
git diff --cached --name-status -z
```

وثائق Git توضح أن `-z` يمنع تعديل أو اقتباس أسماء المسارات ويستخدم `NUL` للفصل، وهو أكثر أمانًا للتحليل البرمجي.
المرجع: [Git diff documentation](https://git-scm.com/docs/git-diff).

وبذلك غالبًا يمكن الاستغناء عن `decode_git_path` بالكامل.

## 4. اختيار مجلد يحتوي اسمه على `clone` غير موثوق

الدالة الحالية تبحث في كل المستويات عن أول مجلد يحتوي اسمه على `"clone"`:

```python
if "clone" in d.lower():
```

المشاكل:

- قد تختار `my-clone-backup`.
- قد تختار مجلدًا داخليًا صغيرًا بدل جذر المشروع.
- نتيجة `os.walk` ليست معيارًا جيدًا لاختيار المشروع.
- يمكن لأرشيف متعمد وضع مجلد باسم `clone` لإجبار السكريبت على رفع جزء محدد.
- البحث في كل العمق غير ضروري.

### الحل المقترح

ترتيب منطقي:

1. إذا كان جذر الأرشيف يحتوي مجلدًا واحدًا فقط، استخدمه.
2. إذا وُجد ملف تعريف مثل `upload-manifest.json`، استخدم `source_root` منه.
3. دعم خيار صريح:
   ```text
   --source-root folder_name
   ```
4. لا تبحث عن كلمة `clone` في جميع مستويات الأرشيف.
5. إذا وُجد أكثر من جذر محتمل، أوقف العملية بدل الاختيار العشوائي.

# 1) ملخص مراجعة الكود الحالي

## المشكلات المؤكدة

| الجزء | المشكلة | التأثير |
|---|---|---|
| `tar.extractall()` | لا يوجد فحص يدوي شامل قبل الاستخراج | احتمال Path Traversal / Tar Slip، خصوصًا مع إصدارات Python القديمة |
| عناصر TAR | الروابط والملفات الخاصة غير مرفوضة صراحة | قد تُنشأ روابط أو أجهزة أو FIFO |
| حدود الاستخراج | لا يوجد حد للحجم أو عدد العناصر | Archive Bomb واستهلاك القرص/الذاكرة |
| `run_cmd()` | يطبع جميع معاملات الأمر عند الفشل | رابط Git الموثق قد يكشف التوكن |
| `copy_tree()` | يعمل كـ Merge فقط | الملفات المحذوفة من الأرشيف تظل داخل المستودع |
| تعارض الأنواع | لا يعالج تحول ملف إلى مجلد أو العكس جيدًا | أخطاء نسخ أو بقايا غير صحيحة |
| Git Diff الحالي | تحليل نصي بالأسطر والمسافات | يفشل مع المسافات، الأسطر الجديدة، Tabs وبعض الأسماء غير المعتادة |
| حالات Git | يعالج `A` و`M` فقط | يتجاهل `D` و`R` |
| حذف فقط | إذا كانت كل التغييرات محذوفات فسيُعتبر أنه لا توجد تغييرات | لا يتم عمل Commit للحذف |
| Rename | المسار يحتوي عادةً على مسارين | المحلل الحالي غير قادر على تحليله |
| `decode_git_path()` | حل يدوي هش ومبني على quoting | يصبح غير ضروري عند استخدام `-z` |
| الألوان | لا توجد دوال دلالية موحدة ولا `MAGENTA` أو `DIM` | تجربة Terminal غير متناسقة |
| `get_source_root()` | يختار أول مجلد يحتوي اسمه على `clone` في أي عمق | اختيار غير حتمي وقد يرفع مجلدًا غير مقصود |

# 2) قرارات التصميم قبل التنفيذ

## القرار 2.1 — أوضاع المزامنة

### `merge`
- الوضع الافتراضي للمحافظة على السلوك الحالي.
- يضيف الملفات الجديدة.
- يستبدل الملفات المعدلة.
- لا يحذف ملفات المستودع غير الموجودة في الأرشيف.
- يعالج تعارض ملف/مجلد.

### `mirror`
- يجعل محتوى المستودع مطابقًا لمحتوى `source_root`.
- يحذف الملفات والمجلدات القديمة غير الموجودة في المصدر.
- يمنع حذف `.git`.
- يمكن إضافة قائمة استثناءات مستقبلية إذا لزم الاحتفاظ بمسارات مثل `.github`.

**القرار المقترح:** الوضع الافتراضي `merge` لمنع أي حذف مفاجئ.

---

## القرار 2.2 — حدود TAR الافتراضية

قيم ابتدائية قابلة للتعديل كثوابت أو خيارات CLI:

- الحد الأقصى لحجم الأرشيف المضغوط: **1 GiB**
- الحد الأقصى للحجم المتوقع بعد الفك: **4 GiB**
- الحد الأقصى للملف الواحد: **1 GiB**
- الحد الأقصى لعدد العناصر: **100,000**
- السماح فقط بـ:
  - Regular files
  - Directories
- رفض:
  - Symbolic links
  - Hard links
  - FIFO
  - Block/character devices
  - Sparse أو الأنواع غير المعروفة

هذه الحدود تحتاج تعديلًا إذا كانت الأرشيفات الفعلية أكبر.

---

## القرار 2.3 — تحليل Git

الأمر المستهدف منطقيًا:

```text
git diff --cached --name-status -z -M
```

- `-z` يمنع quoting ويستخدم فاصل NUL.
- `-M` يفعّل اكتشاف إعادة التسمية.
- الحالات المطلوبة:
  - `A`: ملف جديد
  - `M`: ملف معدل
  - `D`: ملف محذوف
  - `Rnn`: إعادة تسمية، بمسار قديم ومسار جديد

توثيق Git يؤكد أن `-z` مع `--name-status` يعيد المسارات دون تعديل، ويستخدم NUL كفاصل:
[Git diff documentation](https://git-scm.com/docs/git-diff)

**الاختبار الفوري:**

**معيار القبول:**

## MT-1.3 — إنشاء دالة لفحص مسار كل عنصر

**التعديل:**
- تطبيع اسم العنصر.
- رفض:
  - المسار الفارغ غير الصالح.
  - المسارات المطلقة.
  - مسارات Windows ذات Drive مثل `C:`.
  - UNC paths.
  - مكونات `..`.
  - المسارات التي تخرج من `extract_dir`.
- استخدام مقارنة مبنية على `realpath/commonpath` أو ما يكافئها.

**مهم:**
- يجب اعتبار `/` و`\` عند التحقق، خصوصًا على Windows.

**الاختبار الفوري:**

| المسار | النتيجة |
|---|---|
| `folder/file.txt` | قبول |
| `../file.txt` | رفض |
| `folder/../../file.txt` | رفض |
| `/tmp/file.txt` | رفض |
| `C:\temp\file.txt` | رفض |
| `\\server\share\file.txt` | رفض |

**معيار القبول:**
- لا يمكن لأي عضو أن يكتب خارج مجلد الاستخراج.

## MT-1.4 — السماح بالملفات والمجلدات فقط

**الاختبار الفوري:**

**معيار القبول:**
- الأرشيف الذي يحتوي أي عنصر غير مسموح لا يتم فكّه.

**معيار القبول:**

## MT-1.6 — منع تعارضات أسماء TAR الخطرة

**التعديل:**

**معيار القبول:**

## MT-3.6 — تنفيذ Mirror Mode

**معيار القبول:**
