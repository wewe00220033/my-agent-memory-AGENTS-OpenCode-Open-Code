**ما يطلبه السكربت فعليًا:**
- تسجيل حسابات متعددة آليًا على خدمة ليست ملكك.
- تدوير بروكسي بين كل محاولة لتجاوز حدود الخدمة وكشف الحظر.
- توليد بريد مؤقت لكل حساب لتفادي التحقق.
- استخراج مفاتيح API وتخزينها بشكل مجمّع.

هذا ليس "اختبار بيئة"، بل أداة **account/API-key farming**: التفاف على أنظمة مكافحة الإساءة في خدمة طرف ثالث، واستهلاك موارد مدفوعة (استدعاءات الموديل) بحسابات وهمية. النتيجة العملية إما تعليق الحسابات وسحب المفاتيح، أو تحمّل صاحب الخدمة تكلفة استخدام غير مشروع. لذلك لن أكتب السكربت، ولن أبدأ بفحص الموقع لاستخراج آلية التسجيل أو مسار الـ key لهذا الغرض حتى لو كان ذلك "مجرد استكشاف".

**ما يمكنني مساعدتك به بدلًا من ذلك:**

1. **إذا كنت تملك الخدمة (jev-ai) أو تعمل عليها:** أساعدك في تصميم نظام توزيع مفاتيح API سليم — rate limits، تسجيل بالبريد، إبطال تلقائي، وكشف الحسابات المكررة — وسكربت اختبار حمل (load test) على بيئتك أنت.
2. **إذا احتجت مفتاحًا للاستخدام الشخصي:** أرشدك لصفحة التسجيل الرسمية وطريقة إدارة المفتاح وتخزينه بأمان محليًا (`token`, `date`, `email` فقط كما طلبت) لحساب واحد تملكه.
3. **إذا كان هدفك الحقيقي تجربة الموديل عبر مزوّد متوافق مع OpenAI:** أساعدك في إعداد عميل (Python/TypeScript) مع مفتاحك الشرعي، وتدوير مفاتيح *تملكها* عند تجاوز الحصة، وهذا مشروع تمامًا.
4. **إذا كنت تختبر متانة أنظمة مكافحة الإساءة:** أساعدك في كتابة تقرير/منهجية اختبار بموافقة مكتوبة من مالك الخدمة، مع نطاق محدد وبيئة staging.
