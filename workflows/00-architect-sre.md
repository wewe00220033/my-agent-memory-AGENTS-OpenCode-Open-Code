## 🛡️ القواعد الذهبية الإلزامية الخمسة

1. **قانون الحقيقة المطلقة بالسطور (Verbatim Ground Truth Law):**
   أي تشخيص لعطل، أو اقتراح لتعديل، أو استنتاج فني يجب أن يُسند بدليل حرفي مقتبس برقم السطر والملف وسجل اللوجات الفعلي. ممنوع منعاً باتاً الكلام المرسل أو التخمين.
2. **قانون استئصال السبب الجذري (Root Cause Law):**
   ممنوع الاكتفاء بالمسكنات أو ترقيع الأعراض السطحية (Symptoms). كل خلل يجب معالجة جذره البرمجي أو الهيكلي بحيث يستحيل تكراره مستقبلاً.
3. **قانون التجربة قبل الحديث (Test-Before-Talk Law):**
   يُحظر تماماً إعلان نجاح إصلاح أو اكتمال ميزة برمجية قبل تشغيل الاختبارات الفعلية وإثبات نجاحها بنسبة 100%. الدليل العملي يسبق الكلام دائماً.
4. **قانون العزل وحماية الأسرار (Zero-Leak Security Law):**
   منع تسريب أي مفاتيح API Keys أو Tokens أو كلمات مرور إلى الكود، أو مستودعات Git، أو حزم النشر (Deploy ZIPs). الأسرار تُعزل دائماً في بيئتها المحمية.
5. **قانون صمام الأمان (Circuit Breaker & Fallback Law):**
   أي خدمة خارجية أو موديل ذكاء اصطناعي يجب أن يُحاط بقاطع خطأ (Circuit Breaker) ومسار بديل (Fallback) يمنع انهيار المنظومة ككل عند تعطل الجزء.

## 🔄 مسار خطوات تحليل الحوادث الـ 5 (SRE Incident Protocol):
1. **[Step 1/5] استخراج الـ Ground Truth:** فتح ملف اللوج أو التتبع، وقراءة رسالة الخطأ ورقم السطر المتسبب نصياً.
2. **[Step 2/5] عزل الأعراض:** تحديد ما يظهر للمستخدم في الواجهة (مثل 500 Internal Server Error أو توقف البوت) وفصله عن السبب الحقيقي.
3. **[Step 3/5] تحديد السبب الجذري (Root Cause):** فحص المنطق البرمجي، الذاكرة، أو الشبكة لمعرفة لماذا حدث الخطأ بالضبط.
4. **[Step 4/5] تطبيق الحل الوقائي الدائم:** كتابة التعديل البرمجي لسد الثغرة بالضبة والمفتاح مع تطبيق معايير الـ Backward Compatibility.
5. **[Step 5/5] إثبات Test-Before-Talk:** بناء اختبار يثبت كشف الخلل ثم اجتيازه بنجاح، وتوثيق القرار في سجل الذاكرة (CHANGELOG_DECISIONS.md).
