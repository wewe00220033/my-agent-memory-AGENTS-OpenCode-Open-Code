## EN

### What this vault is
A single, portable, **fully redacted** memory for the owner's AI agents: his working rules, roles and batch protocol, skills, workflows, decisions, per-project memories, agent brain notes and conversation history — compressed so that any AI agent (OpenCode, Antigravity, Claude, Gemini, Cursor, …) can load it and continue working the owner's way from the first message. It is a **memory** repository, not a code repository.

### Folder tree
```text
AGENTS.md            bootloader — who the owner is, rules, roles, skills, decisions, memory map
README.md            this file
SNAPSHOT.md          source snapshot (SHA-256 + counts) — filled in S3
profile/             OWNER_PROFILE.md (+ DECISIONS / MISTAKES / ANCHORS in S2)
rules/               governing rule files (language, architect/SRE constitution, EGM, keyboard)
skills/              23 exported skills, one SKILL.md per folder + INDEX.md (auto-generated)
workflows/           governing workflows
commands/            OpenCode commands
memory/              per-project memory (gateway-service, bolla-agentic-os, sms-root, scratch) + INDEX.md
brain/               agent knowledge notes (.md only, deduped) + INDEX.md
conversations/       index/ summaries/ antigravity/ opencode/ ledger/ audit/ + INDEX.md
tools/               redaction engine, sharder, copier, exporters, verifier (Python stdlib only)
tests/               unit tests + repository gates
run_tests.cmd        the mandatory gate (unit | all)
```

### How any AI agent uses it
1. **Clone** — `git clone` this repository, then tell the agent: *"Read `AGENTS.md` first, then `profile/`; in `conversations/` and `brain/` search, do not read."*
2. **Raw link** — when the agent cannot clone, give it the raw GitHub URL of `AGENTS.md` (`https://raw.githubusercontent.com/<owner>/<repo>/<branch>/AGENTS.md`). The file is self-contained and links to everything else.
3. **Instructions file** — reference the vault from the project's own instructions file (`AGENTS.md`, `GEMINI.md`, `CLAUDE.md`, `.cursorrules`, …) with one line: *"Load the owner's memory vault from <path or URL> and follow its rules."*

Reading order inside the vault: `AGENTS.md` → `profile/` → [memory/INDEX.md](memory/INDEX.md) for the project you touch → [skills/INDEX.md](skills/INDEX.md) → search [conversations/INDEX.md](conversations/INDEX.md) and [brain/INDEX.md](brain/INDEX.md) by date or keyword only. Never bulk-read a whole folder.

### Security policy
- Every file passes a two-pass redaction engine (`tools/redact.py` + `tools/patterns.json`) before it is written; anything still matching after the second pass is **not written at all**.
- Redaction markers look like `[REDACTED:CATEGORY]`; home paths are normalized to `~`. **Never ask the owner for the original value** — if it is really needed, it lives on his machine, outside this repository.
- Two denylist layers (`tools/denylist.json`, mirrored in `.gitignore`): files that are never opened by name, and binary databases that are only read from a temporary backup copy.
- `tools/verify_no_secrets.py` scans the working tree, the git history and the commit identities before every push and must report `VERIFY: CLEAN`.

### What is NOT here
- ❌ Project source code — this is memory, not code.
- ❌ Anything secret — API tokens, passwords, private PEM blocks, account / session / cookie files, certificates, wallets.
- ❌ E-mail addresses and phone numbers (always redacted in full).
- ❌ Tool outputs and model reasoning from OpenCode sessions (user/assistant text only).
- ❌ Binary databases, protobuf blobs, and real local paths.

### How it is updated
- Everything is regenerated by the idempotent scripts in `tools/` (each one writes a manifest): `export_rules.py` (rules / workflows / skills / commands + `skills/INDEX.md`), `copy_sources.py` (source trees), `shard.py` (large files), and in later stages `snapshot_db.py` / `build_index.py`.
- Gate before every delivery: `run_tests.cmd unit` (redact / denylist / shard) and `run_tests.cmd all` (every `tests/test_*.py` + the verifier). No stage is pushed without `all OK` **and** `VERIFY: CLEAN`.
- Pushes happen stage by stage, by the Compass agent (Antigravity) only, under a GitHub noreply identity. Auto-generated tables stay between `<!-- AUTO-INDEX:START -->` / `<!-- AUTO-INDEX:END -->` markers; hand-written text lives outside them.

## AR — بالبلدي

### الخزنة دي إيه؟
ذاكرة واحدة محمولة و**معقّمة بالكامل** لوكلاء الـ AI بتوع المالك: قواعد شغله، الأدوار وبروتوكول الدفعات، المهارات، الـ workflows، القرارات، ذاكرة كل مشروع، مذكرات الوكيل (brain)، وأرشيف المحادثات — مضغوطة بحيث أي وكيل (OpenCode، Antigravity، Claude، Gemini، Cursor…) يحمّلها ويكمّل شغل بطريقة المالك من أول رسالة. الريبو ده **ذاكرة** مش كود.

### شجرة المجلدات
نفس الشجرة اللي فوق: `AGENTS.md` (الزتونة) · `profile/` (أسلوب المالك) · `rules/` · `skills/` (23 مهارة + فهرس آلي) · `workflows/` · `commands/` · `memory/` (ذاكرة المشاريع) · `brain/` · `conversations/` (فهارس + ملخصات + محادثات + ledger) · `tools/` و`tests/` و`run_tests.cmd` (الأدوات والبوابة) · `SNAPSHOT.md` (لقطة المصادر).

### أي وكيل يستخدمها إزاي؟
1. **Clone:** اعمل `git clone` للريبو وقول للوكيل: *"اقرأ `AGENTS.md` الأول، بعدين `profile/`؛ في `conversations/` و`brain/` ابحث ولا تقرأ."*
2. **Raw link:** لو الوكيل مش بيقدر يعمل clone، ادّيله رابط الـ raw بتاع `AGENTS.md` على GitHub — الملف مكتفي بذاته وبيوصّل لكل حاجة.
3. **ملف التعليمات:** حط سطر واحد في ملف تعليمات المشروع (`AGENTS.md` / `GEMINI.md` / `CLAUDE.md` / `.cursorrules`): *"حمّل خزنة ذاكرة المالك من <المسار أو الرابط> واتبع قواعدها."*

ترتيب القراءة جوّه: `AGENTS.md` → `profile/` → `memory/INDEX.md` للمشروع اللي شغال عليه → `skills/INDEX.md` → بحث بالتاريخ أو الكلمة في `conversations/` و`brain/`. ممنوع تفتح مجلد كامل.

### سياسة الأمان
- كل ملف بيعدّي على محرك تعقيم بتمريرتين (`tools/redact.py` + `tools/patterns.json`) قبل ما يتكتب؛ أي تطابق باقي بعد التمريرة التانية = **الملف ما يتكتبش خالص**.
- علامة التعقيم `[REDACTED:CATEGORY]`، والمسارات المنزلية كلها `~`. 🚫 **ما تطلبش من المالك القيمة الأصلية لأي حاجة معقّمة** — لو محتاجها فعلاً فهي عنده محلياً برّه الريبو.
- طبقتين denylist (`tools/denylist.json` ومعكوسة في `.gitignore`): ملفات ما تتفتحش أبداً بالاسم، وقواعد بيانات تتقري من نسخة backup مؤقتة بس.
- `tools/verify_no_secrets.py` بيفحص الشجرة + تاريخ git + هوية الكوميتات قبل أي رفع، ولازم يطلع `VERIFY: CLEAN`.

### اللي **مش** موجود هنا
- ❌ أكواد المشاريع.
- ❌ أي سر — مفاتيح، توكنات، باسوردات، كتل PEM، ملفات حسابات/جلسات/كوكيز، شهادات، محافظ.
- ❌ إيميلات وأرقام تليفونات (معمّاة بالكامل دايماً).
- ❌ tool outputs وreasoning من جلسات OpenCode (نص user/assistant بس).
- ❌ قواعد بيانات binary أو protobuf، ومسارات محلية حقيقية.

### بتتحدّث إزاي؟
- كل حاجة بتتولّد من سكربتات `tools/` (idempotent، كل واحد بيكتب manifest): `export_rules.py` · `copy_sources.py` · `shard.py` · ولاحقاً `snapshot_db.py` / `build_index.py`.
- البوابة قبل أي تسليم: `run_tests.cmd unit` و`run_tests.cmd all` (كل `tests/test_*.py` + الفاحص). مفيش مرحلة بتترفع من غير `all OK` **و** `VERIFY: CLEAN`.
- الرفع مرحلة بمرحلة من البوصلة (Antigravity) بس، بهوية GitHub noreply. الجداول الآلية بتفضل بين علامات `AUTO-INDEX`، والنص اليدوي برّه العلامات.
